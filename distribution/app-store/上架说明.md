# Mac App Store 准备情况

版本：1.3（6）。这份记录区分本地准备与苹果审核，不代表应用已经上架。

## 已完成的项目改造

- 应用开启 App Sandbox，仅访问用户选择的文件；支持保留解压后文件的可执行属性，不执行这些文件。不申请网络或临时权限例外。
- 读取、预览、压缩和解压在整个处理期间保持必要的文件访问；保留系统选择窗口传入的原始文件地址。
- 压缩使用系统提供的同卷临时保存位置，避免在未授权的文件夹里创建中间文件。完成前保留原有压缩包。
- 从访达或系统服务打开压缩包时，先选择保存文件夹；取消不会开始解压。批量请求继续排队处理。
- 最近记录保存文件访问凭据，应用重启后可以定位结果；兼容旧版没有凭据的记录，失效时显示提示。清空记录同时删除这些凭据。
- 包含隐私声明：只保存应用自身偏好，读取用户选中文件及应用自己的临时文件信息；不跟踪、不收集数据。
- Yuya 菜单提供“隐私说明”，在应用内解释文件处理、本机记录、访问凭据和清空方式。
- 正式图标保留小丑鱼和拉链，使用 Mac 原生图标；原有 DMG 打包方式保留。
- 修复桌面启动环境下的中文 ZIP 文件名标记，使用独立 ZIP 读取器核对名称与内容；不会修改其他线程的语言环境。
- `AppStore` 构建配置及共享 `Yuya` 方案已加入；商店归档同时构建 Apple 和 Intel 芯片版本。

## 构建入口

本地验收归档（不向苹果提交，不访问开发者账号）：

```sh
./scripts/test.sh
python3 scripts/check_unicode.py
./scripts/archive-store.sh local
```

归档位置：`build/AppStore-local/Yuya.xcarchive`。其中应用经过本机临时签名，仅用于检查，不能上传商店。

正式签名归档会由 Xcode 访问开发者账号、创建或更新应用标识及签名配置，必须先确认使用的团队。设置真实的团队编号后运行：

```sh
./scripts/archive-store.sh signed
```

脚本从环境变量 `YUYA_TEAM_ID` 读取团队编号，自动签名归档默认使用 `Apple Development`；导出到 App Store Connect 时由 Xcode 选择发布证书。不会自动上传、提交审核或修改价格。

正式归档位置：`build/AppStore-signed/Yuya.xcarchive`。在 Xcode 中打开归档，先校验，再选择分发至 App Store Connect。上传需已有相应应用记录，应用编号必须与项目一致。不得把普通 DMG 当作商店上传文件。
